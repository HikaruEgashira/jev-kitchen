# UIを厨房と同じThreeシーンで描画する

採用。HTML/CSSのHUDとThreeの厨房で、見た目・入力状態・ダイアログ判定が重複していた。

移行はラベル、画面UI、文字と商品の順に行う。`ui.js`が画面と操作を記述し、`SceneUI.jsx`がThreeの看板と操作用DOMへ同じ内容を渡す。停止やメニューの判定はゲーム状態に置く。

可視UIはThreeのメッシュ、通常の文字はGlyph、固定表示・追従・角丸形状はDreiを使う。タイトルのみDrei Text3Dで厚みのある文字を作る。商品モデルは注文票と厨房で共有する。開始画面は上部のタイトル看板と下部の開店操作に限定し、中央の厨房を見せる。HUD・注文・スタッフ名・在庫は開始後に表示する。文字には必ず看板を敷く。スマホ幅では文字を縮小し、操作領域は44px以上を保つ。

OSの数値編集、キーボード、スクリーンリーダーは不可視のネイティブ要素で維持する。モーダル中は背面操作を無効にし、Tabをダイアログ内に留める。WebGPU初期化・再接続の案内だけはCanvas外に置く。

GlyphのフォントはCanvas単位で保持する。各ラベルで取得すると、画面遷移で破棄されたフォントを別の段落が参照するためである。M PLUS Rounded 1c Boldを同梱し、`pnpm fonts`で表示文字をMSDFへ焼く。生成・読込ともemSizeは32とし、build時に未収録文字を検査する。

Glyph 0.1 / Three r186では、geometryの破棄が共有storage bufferまで破棄し、残る段落のbind groupを無効にする。Threeへのpnpm patchでstorage bufferの解放を所有者の`BufferAttribute.dispose()`まで遅らせる。通常のgeometry属性の解放は変えない。回帰テストは共有中の保持と所有者による一度だけの解放を検証する。ライブラリ更新時は文字更新・メニュー開閉・リサイズ・GPU再接続を反復確認し、上流修正後にpatchを外す。

WebGPU必須の構成は維持する。uikitのWebGL用パネルマテリアルは混在させない。画像フォントを自作したり、HTML用の見た目を再び実装したりしない。
