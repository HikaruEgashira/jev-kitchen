# 成長する厨房と交代制の相棒

## 決定

ゲーム状態を唯一の正とし、90秒の営業終了時にノルマで合否を判定する。星は得点評価であり、合否とは分離する。次の営業への進行が設備・移動範囲・注文を同時に解禁する。

解放条件、注文、同時出勤上限は`src/progression.js`の`levelConfig`を唯一の正とする。Lv1〜100の個別設定表は作らない。

| 到達Lv | 新しい判断                              | 相棒の同時出勤上限 |
| ------ | --------------------------------------- | ------------------ |
| 1      | サラダの仕込み・盛り付け・配膳          | 1人                |
| 5      | 鍋の12秒加熱中に別の仕事を進める        | 1人                |
| 10     | グリルの7秒加熱と鍋を並行する           | 2人                |
| 15     | 作業の25〜65%で空手の手動ブーストを狙う | 2人                |
| 20     | 鍋・グリルの完成品を焦げる前に回収する  | 3人                |
| 25     | 連勤上限と休養期間から次の出勤を選ぶ    | 3人                |
| 30     | ラッシュの追加注文に対応する            | 4人                |

Lv31以降は新設備・新ルールを増やさない。`L`を1〜100に制限し、`t = max(0, (L - 30) / 70)`とする。

- ノルマ: Lv30までは`6 + floor(L / 5)`、以降は`12 + round(2 × sqrt(t))`。
- 注文猶予（秒）: Lv30までは`36 - 12 × sqrt(min(5, floor(L / 5)) / 5)`、以降は`24 - 4 × sqrt(t)`。
- スープ比率: Lv5以降、`0.40 - 0.05 × (L - 5) / 95`。
- グリル比率: Lv10以降、`0.20 + 0.10 × (L - 10) / 90`。
- サラダ比率: 残り。未開放の商品は比率0とする。

最初の注文2枚は待ち時間の1倍・4/3倍で期限をずらす。補充注文は1倍。注文番号から再現可能な分散列を作り、累積比率で商品を選ぶ。再挑戦で乱数の偏りを引き直すことはない。

Lv100はノルマ14皿、猶予20秒、商品比率35/35/30%となる。旧加熱時間での自動方策の達成例を、新構成の実プレイ証拠として流用しない。

採用、出勤、仕入れは営業間に集約する。未採用の応募者最大三名から一名を雇うか見送り、所有する従業員から出勤者を選ぶ。Lv2以降の有限在庫と採用費・給与は共通の財布を使い、ノルマ以上の在庫、出勤上限、休養、支払能力を検証してから一括確定する。

設備価格・効果・上限は`src/equipment.js`に集約する。まな板・鍋・グリルは各2台、改良は各Lv3まで。Lv20の保温台は焦げ猶予を延ばす。厨房拡張は3段階で、追加設備枠を1／2／4、横幅加算を0／130／260とする。レベル解放の基本設備は無料で維持し、資金不足で新レシピが作れなくなる状態を避ける。

設備と採用の価格は`investmentCost`で、基準手残り90コイン×投資ごとの貯蓄営業数を5コイン単位に丸める。基準はLv2の6皿×売上25−食材48−給与12。改良は1.5〜4単位、増設3〜6単位、厨房拡張8／12単位、採用3〜16単位とする。後半の実手残りは増えるため、この単位は全レベルの実所要営業数を意味しない。初回クリアで小改良は可能だが、増設・採用と開店費の同時支払いはできない。貯蓄中に目標価格が上がらないよう、レベル連動の物価上昇は設けない。

設備は固定区画へ移設・入替する。自由座標のドラッグは扱わず、配置を`stationId → slotId`として保存する。移動・AI候補・描画は同じ配置を参照する。設備枠、区画の重複、購入費を検証し、採用・仕入れ・給与と一括確定する。準備中の表示だけでは財布・保存データを変更しない。

従業員ごとに担当工程・移動速度・調理時間・ダッシュ・判断間隔が異なる。Lv25から連勤を記録し、休みを挟まず上限まで働くと職種ごとの強制休養に入る。休養はクリア時に一度だけ進める。失敗の反復では資金や休養を稼げない。

複数の従業員は独立した行動を持ち、共用設備の予約と到着時の再検証で競合を避ける。Jevは合法な候補から選び、通信中・移動中の重複要求を避ける。短い判断間隔は反応頻度であり、モデルの推論精度を保証しない。右上のスタッフ一覧は閲覧専用とし、方針入力・判断方式・個別能力の設定は置かない。

入口は「開店」一つにする。初回の一皿だけ固定注文と操作ガイドを使い、配膳後は同じ厨房で通常営業へ連続して移行する。

## 理由と境界

固定厨房の往復と無操作の高得点ではプレイヤーの判断価値が低い。設備拡張、同時調理の焦げ、手動アシスト、採用への再投資で状況を変える。

営業開始時の状態を端末内に保存する。失敗時は同条件での再挑戦、直前の開店準備の見直し、前ステージからのやり直しを区別する。巻戻しは資金・在庫・雇用・疲労・設備・厨房拡張・配置を一括復元し、応募者の再抽選や報酬の二重取りを防ぐ。任意時刻の無制限undoやクラウド同期は扱わない。営業中は注文と厨房に集中させ、勤務表は営業間、診断と操作設定は停止中に置く。
